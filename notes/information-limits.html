15 The data processing inequality

Key resultinformation cannot be created by processing

If \(T\to X\to S\) is a Markov chain, meaning the signal \(S\) is computed from \(X\) alone, then \[I(T;S)\le I(T;X).\]

Take \(T\) to be the truth, \(X\) the problem together with the model, and \(S\) any label-free signal built from the model’s own samples: votes, confidence, consistency checks. No such signal carries more information about the truth than the model already holds. Label-free self-play can extract and concentrate that information; it cannot create it. To expand, the loop needs an outside source (an executor, a proof checker, an environment) or an asymmetry such as checking being easier than solving.

An important nuance. The inequality bounds information, not usability. A model can “know” an answer at pass@256 and still fail at pass@1. Turning latent knowledge into reliable behavior is real value; it is sharpening, not new knowledge.

16 The generator–verifier gap

Key resultfiltering helps only if checking beats chance

Filter self-generated answers with the model’s own check, with \(\mathrm{TPR}=\Pr(\text{accept}\mid\text{correct})\) and \(\mathrm{FPR}=\Pr(\text{accept}\mid\text{wrong})\). By Bayes’ rule, the accuracy among accepted answers is \[\begin{gathered}\mathrm{prec}=\frac{p\,\mathrm{TPR}}{p\,\mathrm{TPR}+(1-p)\,\mathrm{FPR}}, \\[4pt] \text{and} \\[4pt] \mathrm{prec}>p\iff\mathrm{TPR}>\mathrm{FPR}.\end{gathered}\]

Proof. \(\mathrm{prec}>p\iff\mathrm{TPR}>p\,\mathrm{TPR}+(1-p)\mathrm{FPR}\iff(1-p)\mathrm{TPR}>(1-p)\mathrm{FPR}\).

Examplea useful and a useless verifier

\(p=0.3\), \(\mathrm{TPR}=0.9\), \(\mathrm{FPR}=0.2\): \(\mathrm{prec}=0.27/(0.27+0.14)=0.659\), more than double the base accuracy, so training on accepted answers can help. If \(\mathrm{TPR}=\mathrm{FPR}\), then \(\mathrm{prec}=p\) and filtering adds nothing.

Song et al. (2025) formalize this generation–verification gap and study how it varies across models and verification methods. It is the cleanest statement of when self-improvement is possible at all.

Why it matters

A majority vote is a verifier too: its TPR and FPR come from how often right and wrong answers become the mode. When errors are shared, a wrong answer becomes the mode as easily as a right one, and the gap closes.

Exercises

Exercise 10. A verifier has \(\mathrm{TPR}=0.8\) and \(\mathrm{FPR}=0.4\) on a problem set with \(p=0.2\). What is the accuracy of the accepted answers?

Show answer

\(0.16/(0.16+0.32)=0.333\), above the base \(0.2\), so filtering helps.
